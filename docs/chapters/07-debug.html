デバッガは「目」である

エミュレータ開発では「画面が真っ黒」「キャラが化ける」といった不具合が日常です。 原因は CPU・PPU・マッパーのどこにでもあり得るので、 各段階の中間状態を見える化できると切り分けが一気に楽になります。

ビュー見えるものこれで分かる不具合
パターンテーブルCHR-ROM のタイル 512 枚(絵の辞書)絵が化けている → CHR バンク切替のバグ
ネームテーブル4 画面分のタイル配置+ミラーリング配置が変 → VRAM 書き込み/ミラーのバグ
パレット現在の 32 色色が変 → パレット RAM のバグ
CPU 状態PC/A/X/Y/SP/フラグ/サイクル暴走 → 命令実装のバグ
実行トレース逆アセンブル付きの実行履歴「どこで」おかしくなったか

エミュレータの内部データ(ppu.vram、mapper.ppuRead() など)を そのまま Canvas に描くだけなので、実装は意外に簡単です。 「🔍 デバッグ表示」ボタンで開き、重いビューは 15 フレームに 1 回だけ更新して負荷を抑えています。

ミニ逆アセンブラ

CPU トレースは実行中の命令を C123 LDA $2002 A:00 X:05 ... のように表示します。 第2章で作ったオペコードテーブルに「この命令は何バイトか」を問い合わせるだけで、 逆アセンブラのコアは 20 行で書けます(opcodeInfo())。

タイミング — リフレッシュレート問題

これまで requestAnimationFrame(rAF)ごとに 1 フレーム実行していましたが、 これには罠があります。rAF はディスプレイのリフレッシュレートで呼ばれるため、 120Hz のゲーミングモニタではゲームが 2 倍速になってしまうのです。

解決策は「経過時間の積算」です:

const FRAME_MS = 1000 / 60.0988;   // NTSC の正確なフレームレート
accumulator += now - lastTime;
while (accumulator >= FRAME_MS) {  // 溜まった時間の分だけ実行
  nes.runFrame();
  accumulator -= FRAME_MS;
}

これで 60Hz でも 120Hz でも 144Hz でも正しい速度になります。 タブがバックグラウンドから復帰したときに溜まった時間で暴走しないよう、 積算の上限も設けています。

パフォーマンス最適化

最適化の鉄則は「計測してから直す」。ヘッドレスベンチマークで計測すると:

600 フレーム実行: 414 fps = 実機の約 6.9 倍速 (Node.js)

60fps の約 7 倍の余裕があるので大改造は不要ですが、効果の大きい定石を適用しました:

  • ホットループでオブジェクトを作らない — PPU のライン描画で毎回 new Uint8Array(256) を 4 本作っていたのを、 インスタンスフィールドの使い回しに変更(1 フレームで 960 回の GC 対象を削減)
  • 型付き配列 — フレームバッファは Uint32Array。 1 ピクセル 1 要素で、ImageData のメモリと直接互換
  • 画面転送は 1 回 — putImageData を毎フレーム 1 回だけ
  • テーブル駆動 CPU — 命令デコードは配列参照 1 回
  • デバッグ表示の間引き — 重いビューは 1/15 頻度、トレースは opt-in
JavaScript エンジン (V8) は同じ型の値が流れる単純なループを強力に最適化します。 「クラスのフィールドの型を変えない」「ホットパスで例外や動的プロパティを使わない」 だけで、エミュレータ程度の負荷は余裕で 60fps が出ます。

GitHub Pages で公開

このプロジェクトは最初から「docs/ に全成果物を置く」構成にしてきました。 解説 HTML も、ビルド済みエミュレータ (app.js) も、 オリジナルゲームの ROM も全部 docs/ にあります。公開方法は 2 通り:

  1. ブランチから: リポジトリの Settings → Pages → Source を 「Deploy from a branch」にして、ブランチと /docs フォルダを選ぶ
  2. GitHub Actions から: 同梱の .github/workflows/pages.yml が push のたびに docs/ をそのままデプロイする (Settings → Pages → Source を「GitHub Actions」にする)

この章の動作確認手順

  1. npm run build && npm run serve でブラウザを開き、『MOSS HOP』をロード
  2. 「🔍 デバッグ表示」→ パターンテーブルにモスや文字のタイル、 ネームテーブルにレベル地形、パレットにゲームの配色が見えること
  3. 「CPU トレース」を ON → 逆アセンブル付きの実行履歴が流れること
  4. 「⏸ 一時停止」→「⏭ 1フレーム進める」でコマ送りできること
  5. GitHub Pages 設定後、公開 URL で同じものが動くこと
