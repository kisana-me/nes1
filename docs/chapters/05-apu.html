APU(音声)実装

この章のゴール

NES の音源 APU (Audio Processing Unit) を実装し、エミュレータに音を与えます。 あわせて『MOSS HOP』にジャンプ・アイテム取得・クリアの効果音を追加し、 「ゲームが APU に書いた値が、ブラウザのスピーカーから聞こえる」までを繋ぎます。

実装したファイル:

  • src/apu.ts — APU 本体(5 チャンネル + フレームカウンタ + ミキサー)
  • src/audio.ts — Web Audio API への出力(リングバッファ)
  • game/build-game.ts — 効果音ルーチンを追加

NES の音は「回路」でできている

現代の音楽制作は波形データ(サンプル)を再生しますが、NES の音は デジタル回路が生成する波形そのものです。チャンネルは 5 つ:

チャンネル波形主な用途
パルス 1矩形波 (duty 12.5/25/50/75%)メロディ、効果音
パルス 2矩形波ハモリ、効果音
三角波32 段の擬似三角波ベースライン
ノイズLFSR による擬似乱数ドラム、爆発
DMC1bit デルタ変調サンプルボイス、ドラム

「ファミコンの音」と聞いて思い浮かべるピコピコ音は矩形波の音色です。 duty 比(波形の上下比率)を変えるだけで音色が変わります。 

duty 12.5% : _|‾|______|‾|______   細く鋭い音
duty 25%   : _|‾‾|_____|‾‾|_____   明るい音
duty 50%   : _|‾‾‾‾|___|‾‾‾‾|___   丸く太い音

音程 = タイマー(分周器)

各チャンネルには 11 ビットの「タイマー」があり、CPU クロックを分周して波形を進めます。 タイマー値と周波数の関係は: 

周波数 = 1789773 / (16 × (タイマー値 + 1))   ※パルス波

例: 440Hz (ラの音) を出したい → タイマー = 1789773/(16×440) - 1 ≈ 253

ゲーム機のドレミは、この割り算をあらかじめ計算した「周波数テーブル」で実現されています。

音を「切る」仕組み — 長さカウンタとエンベロープ

CPU が音を止めるまで鳴りっぱなしでは効果音に使いにくいので、APU には自動化機構があります。

  • 長さカウンタ — キーオン時にセットされ、0 になるとチャンネルが無音になる(自動ノートオフ)
  • エンベロープ — 音量 15 から一定速度で減衰(ピアノのような自然な減衰)
  • スイープ — 音程を自動で上下させる(『ピュン』というジャンプ音はこれ)
  • リニアカウンタ — 三角波専用の高精度な長さ制御

これらを 1 秒に約 240 回駆動するのがフレームカウンタです。 $4017 の設定により 4 ステップ/5 ステップのシーケンスで、 エンベロープ(四半フレーム)と長さカウンタ・スイープ(半フレーム)をクロックします。 実装ではこの NTSC 実機のサイクル数 (7457, 14913, 22371, 29829) をそのまま使っています。

ミキサー — 実機の回路をそのまま式に

5 チャンネルの出力は単純な足し算ではなく、実機の抵抗回路に由来する非線形の合成式で混ざります: 

pulse_out = 95.88 / (8128 / (pulse1 + pulse2) + 100)
tnd_out   = 159.79 / (1 / (tri/8227 + noise/12241 + dmc/22638) + 100)
output    = pulse_out + tnd_out

この式は「チャンネルを増やすほど 1 チャンネルあたりの音量が下がる」という 実機の音量感を再現します。エミュレータ界で標準的に使われている近似式です。

ブラウザへの出力 — サンプリングとバッファ

APU は CPU と同じ 1.79MHz で動きますが、ブラウザの音声は 44.1kHz(約 40 サイクルに 1 サンプル)。 そこで ダウンサンプリングします: 

// CPU サイクルごとに:
sampleCounter++;
if (sampleCounter >= 1789773 / 44100) {  // ≈ 40.58 サイクルごと
  sampleCounter -= 1789773 / 44100;
  onSample(mix());                        // 1 サンプル出力
}

生成したサンプルはリングバッファ(src/audio.ts)に貯め、 Web Audio API のコールバックが取り出して再生します。 エミュレータは requestAnimationFrame(描画タイミング)、音声はオーディオスレッドと、 別々のクロックで動くため、バッファが速度差を吸収します。 バッファが空のときは直前の値を出し続けて「プチッ」というノイズを防ぎます。

ブラウザは自動再生を制限しているため、AudioContext は ユーザーのクリック操作(ROM 読み込みボタン)の中で生成しています。

『MOSS HOP』に効果音を追加

ゲーム側からは、APU はただのレジスタ($4000-$4017)です。ジャンプ音はこれだけ:

sfxJump:
  LDA #$44      ; duty 25%, エンベロープ減衰
  STA $4000
  LDA #$8B      ; スイープ有効・negate → 音程が上昇していく
  STA $4001
  LDA #$D0      ; 開始音程 ≈ 233Hz
  STA $4002
  LDA #$49      ; 長さカウンタ 8 (約 130ms で自動停止)
  STA $4003
  RTS

4 バイト書き込むだけで、あとはスイープが音程を上げ、エンベロープが音量を減衰させ、 長さカウンタが音を止めてくれます。ハードウェアが効果音を演奏してくれる—— これが 1983 年の設計の合理性です。ほかに胞子取得の「ピロン」(パルス2、880Hz)と、 クリア時の和音(C5+E5)を実装しました。

この章の動作確認手順

  1. npm test — APU テスト 4 件を含む全件 pass。 testGameJumpSfx は「ジャンプ前は無音サンプルのみ → ジャンプ後に音量のあるサンプルが 500 個以上生成される」ことを検証します
  2. npm run build:game && npm run serve でブラウザを開き、『MOSS HOP』をプレイ
  3. X でジャンプ →「ピュン」、胞子を取る →「ピロン」、 2 レベルクリア →「ピンポーン」(和音) が聞こえれば OK
  4. 「🔊 音声 ON」ボタンでミュートの切り替えができる
