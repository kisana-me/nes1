6502 CPU コア実装

この章のゴール

エミュレータの心臓部である 6502 互換 CPU を実装します。 この章が終わると、NES のゲームプログラム(機械語)を 1 命令ずつ正しく実行できるようになります。 まだ画面も音もありませんが、「計算機として動く NES」が手に入ります。

実装したファイル:

  • src/cpu.ts — CPU 本体(全公式命令 151 個)
  • src/bus.ts — メモリバス(アドレスの振り分け)
  • src/cartridge.ts — iNES ローダー
  • src/mappers/nrom.ts — マッパー 0 (NROM)
  • tests/cpu.test.ts — CPU のユニットテスト

CPU は何をする機械か

CPU の仕事は驚くほど単純で、次の 3 ステップの無限ループです。

  1. フェッチ — PC(プログラムカウンタ)が指すアドレスから 1 バイト読む。これが「命令」
  2. デコード — そのバイト(オペコード)が何の命令か・引数が何バイトかを判別する
  3. 実行 — 命令に応じてレジスタやメモリを変更し、PC を次の命令に進める

エミュレータの CPU も全く同じで、step() メソッドがこの 1 周を実行します。

6502 のレジスタ

6502 はレジスタが非常に少ない CPU です。全部でこれだけ:

レジスタ幅役割
A (アキュムレータ)8bit計算の主役。加算・減算・論理演算はほぼ A に対して行う
X, Y8bitインデックスレジスタ。配列アクセスの添字やループカウンタ
SP (スタックポインタ)8bitスタック($0100-$01FF 固定)の現在位置
PC (プログラムカウンタ)16bit次に実行する命令のアドレス
P (ステータス)8bitフラグの集合(下記)

ステータスフラグ (P レジスタ)

bit:  7 6 5 4 3 2 1 0
      N V - B D I Z C
      │ │     │ │ │ └ Carry    : 繰り上がり / 借りなし
      │ │     │ │ └── Zero     : 結果が 0
      │ │     │ └──── IRQ禁止  : 1 なら IRQ を無視
      │ │     └────── Decimal  : NES では機能しない(フラグは残る)
      │ └──────────── oVerflow : 符号付き計算のオーバーフロー
      └────────────── Negative : 結果の bit7(符号ビット)

実装では P を 1 バイトで持たず、this.c this.z のように 1 ビットずつ分解して保持しています。毎命令ビット演算でフラグを出し入れするより速く、コードも読みやすくなります。 PHP(P をスタックに退避)などが必要なときだけ getP() で合成します。

アドレッシングモード — 6502 理解の最重要ポイント

同じ「LDA(A にロード)」でも、データをどこから持ってくるかで 8 種類のオペコードがあります。 この「どこから」の指定方法をアドレッシングモードと呼びます。

モード記法意味
ImmediateLDA #$10即値。$10 という値そのもの
Zero PageLDA $10アドレス $0010 の中身(先頭 256B は 1 バイトで指定でき速い)
Zero Page,XLDA $10,X$10+X の中身(256B 内でラップ)
AbsoluteLDA $1234アドレス $1234 の中身
Absolute,X/YLDA $1234,X$1234+X の中身。配列アクセス
(Indirect,X)LDA ($10,X)$10+X にあるポインタの先
(Indirect),YLDA ($10),Y$10 にあるポインタ+Y の先。C の ptr[y] に相当
RelativeBNE label分岐専用。PC からの相対距離(±128)

実装では、命令ごとに「何の操作か(LDA)」と「アドレスの計算方法(ZPX)」を分離した テーブル駆動にしました。256 個のオペコードそれぞれに { name, mode, cycles } を登録し、step() は ①モードに従ってアドレス解決 → ②命令名で switch、という 2 段構えです。 これで 151 命令が「56 種類の操作 × 13 種類のモード」に整理され、コード量が大幅に減ります。

サイクル数を正しく数える

各命令には実機での消費サイクル数があります(LDA #imm は 2、STA $1234,X は 5 など)。 これを正確に返すことが重要です。なぜなら第3章以降、 「CPU が n サイクル使ったら PPU を 3n サイクル進める」という方法で CPU と PPU の同期を取るからです。サイクルがずれると画面が乱れます。

さらに細かいルールが 2 つ:

  • ページ境界クロス: LDA $12F0,X で X=0x20 のとき、アドレスが $1310 になり 上位バイト(ページ)が変わる。このとき読み出し系命令は +1 サイクル
  • 分岐: 不成立 2 / 成立 3 / 成立かつページ跨ぎ 4 サイクル

6502 の有名なバグも再現する

エミュレータは実機のバグまで再現する必要があります。ゲームがバグ込みの挙動に依存していることがあるからです。 

// JMP ($02FF) — ポインタがページ境界にあるとき、
// 上位バイトは $0300 ではなく "$0200" から読まれてしまう!
private read16Bug(addr: number): number {
  const lo = this.read(addr);
  const hi = this.read((addr & 0xff00) | ((addr + 1) & 0xff));
  return lo | (hi << 8);
}

ADC — たった 1 命令に詰まった教科書

加算命令 ADC (Add with Carry) はアーキテクチャ学習の宝庫です。

private adc(m: number): void {
  const sum = this.a + m + this.c;        // キャリー込みで加算
  this.c = sum > 0xff ? 1 : 0;            // 9bit 目 = 繰り上がり
  const result = sum & 0xff;
  // 「同符号どうしを足したのに符号が変わった」= 符号付きオーバーフロー
  this.v = (~(this.a ^ m) & (this.a ^ result) & 0x80) !== 0 ? 1 : 0;
  this.a = result;
  this.setZN(this.a);
}
  • C フラグは 8bit を超えた繰り上がり。これを使って 16bit・24bit の多倍長加算ができる
  • V フラグは符号付き(-128〜127)としてのオーバーフロー。C とは別物
  • SBC(減算)は ADC の再利用: A - M = A + (~M) + C(2 の補数)。 実装は this.adc(m ^ 0xff) の 1 行

割り込み — ハードからの「呼び出し」

割り込みは「ハードウェアが CPU に横入りしてサブルーチンを呼ばせる」仕組みです。 現在の PC とフラグをスタックに退避し、ベクタテーブル(ROM 末尾の固定アドレス)から ハンドラのアドレスを読んでジャンプします。

種類ベクタ用途
NMI(マスク不可)$FFFAPPU が毎フレーム VBlank 開始時に発生。ゲームの心拍
RESET$FFFC電源投入・リセットボタン
IRQ / BRK$FFFEAPU・マッパー(MMC3)から。I フラグで無視できる

NES のゲームは実質「NMI 駆動」で動いています。メインループで次フレームの準備をし、 NMI が来たら PPU にデータを流し込む——このリズムは第3章で体感します。

バスとメモリマップ

CPU 自身はメモリの内容を知りません。read(addr) / write(addr, value) を 呼ぶだけです。アドレスをデバイスに振り分けるのが Bus クラス: 

read(addr: number): number {
  if (addr < 0x2000) return this.ram[addr & 0x7ff]; // 2KB を 4 回ミラー
  if (addr < 0x4000) return this.ppu.readRegister(addr & 7);
  if (addr === 0x4016) return this.controller.read1();
  ...
  return this.mapper.cpuRead(addr); // カセットへ
}

addr & 0x7ff の 1 行が「ミラーリング」の実装です。実機ではアドレス線の上位ビットが 配線されていないため、$0000 と $0800 と $1000 と $1800 は同じ RAM セルに繋がっています。

NES の CPU (RP2A03) は 6502 から 10進モード (BCD) を削除したチップです。 D フラグをセットしても加算は普通の 2 進で行われます。エミュレータでも BCD は実装しません。
