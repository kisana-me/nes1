プロジェクト概要と NES アーキテクチャ

この章のゴール

このプロジェクトでは、NES(Nintendo Entertainment System / ファミコン)のエミュレータを TypeScript でゼロから作りながら、コンピュータアーキテクチャの基礎と言語を学びます。 第1章ではコードはほとんど書かず、「NES とはどういう機械なのか」「エミュレータとは何をするプログラムなのか」を 理解することがゴールです。

エミュレータとは何か

エミュレータとは、ある機械(ハードウェア)の振る舞いを、別の機械の上でソフトウェアとして再現するプログラムです。 NES エミュレータの場合、再現する対象は次の 3 つのチップ+周辺回路です。

  • CPU — プログラム(機械語)を 1 命令ずつ実行する頭脳
  • PPU — 画面(背景とスプライト)を描く映像チップ
  • APU — 音(矩形波・三角波・ノイズなど)を鳴らす音源

つまりエミュレータの本体は、巨大な while ループの中で 「CPU を 1 命令進める → その消費サイクル分だけ PPU と APU も進める」を 1 秒間に約 179 万回(CPU クロック 1.789773 MHz)繰り返すプログラムです。 ゲーム側から見ると、本物のハードの上で動いているのと区別が付きません。

現代の PC はメモリが数十 GB ありますが、NES の作業メモリは 2KB です。 このテキストの HTML ファイルよりずっと小さいサイズで、あの名作ゲームたちが動いていました。 制約の中の工夫を知ることが、このプロジェクトの面白さの半分を占めます。

CPU から見た世界 — メモリマップ

6502 CPU は 16 ビットのアドレス($0000〜$FFFF の 64KB 空間)しか知りません。 CPU にとって「PPU に絵を頼む」ことも「コントローラーを読む」ことも、 すべて特定のアドレスへの読み書きとして行われます。これを メモリマップド I/O と呼びます。

アドレス範囲何があるか
$0000-$07FFWRAM 2KB($0800-$1FFF には同じものが 3 回ミラーされて見える)
$2000-$2007PPU レジスタ 8 個($3FFF まで 8 バイト周期でミラー)
$4000-$4013APU レジスタ
$4014OAM DMA(スプライトデータの一括転送)
$4016 / $4017コントローラー 1P / 2P
$6000-$7FFFカセット上の拡張 RAM(セーブ用電池付きのことも)
$8000-$FFFFPRG-ROM(ゲームプログラム本体)

エミュレータではこの表をそのまま Bus(バス)というクラスの read(addr) / write(addr, value) に実装します。 「アドレスによって行き先を振り分ける switch 文」がバスの正体です。

カセットと iNES フォーマット

実機ではゲームはカセット(ROM チップ)として供給されました。エミュレータの世界では、 カセットの中身を吸い出して 1 つのファイルにした iNES フォーマット(拡張子 .nes)が標準です。 構造はシンプルで、16 バイトのヘッダの後に PRG-ROM と CHR-ROM がそのまま並びます。 

+--------------------+
| ヘッダ 16 バイト      |  "NES" + $1A で始まる
|  - PRG-ROM サイズ    |  16KB 単位
|  - CHR-ROM サイズ    |  8KB 単位
|  - マッパー番号 など   |
+--------------------+
| (トレーナー 512B)     |  ※あれば
+--------------------+
| PRG-ROM             |  プログラム本体
+--------------------+
| CHR-ROM             |  グラフィックデータ
+--------------------+

マッパーとはカセット側に載っている「バンク切り替え回路」のことです。 CPU から見える ROM 空間は 32KB しかないため、それより大きいゲームは マッパーで ROM の一部を差し替えながら動きます。本プロジェクトでは、まず回路なしの NROM(マッパー 0)だけに対応し、第6章で MMC1 や MMC3 などに拡張します。

1 フレームの流れ

NES のゲームは次のサイクルを 1 秒間に約 60 回繰り返します。

  1. PPU が画面を上から 1 ラインずつ描画していく(240 ライン)
  2. 描画が終わると PPU が CPU に NMI(割り込み)で「描画終わったよ」と知らせる
  3. CPU は VBlank(画面外走査期間)の間に、次のフレームの絵の内容を PPU に書き込む
  4. その間もゲームロジック(入力を読む、キャラを動かす、音を更新する)が走る

CPU と PPU は並行して動く別々のチップで、PPU は CPU の 3 倍の速度で動きます。 エミュレータでは「CPU が n サイクル使ったら PPU を 3n サイクル進める」という方法で この並行動作を再現します(キャッチアップ方式)。

使う技術

  • TypeScript — 型があることで「このレジスタは 8 ビット」といった制約をコードで表現しやすい
  • Canvas API — PPU が生成した 256×240 のピクセルバッファを putImageData で描画
  • Web Audio API — APU が生成した波形をブラウザで再生(第5章)
  • esbuild — TypeScript を 1 つの JS にバンドル。ビルドは一瞬
このプロジェクトでは既存の商用ゲーム ROM は一切使用しません。 動作確認には、第4章で作る完全オリジナルの 2D プラットフォーマーゲーム (オリジナルキャラクター・オリジナル世界観)を使います。

開発の進め方

各章は次のサイクルで進めます。

  1. 機能を実装する
  2. git で新規ブランチを切る(例: feature/02-cpu-core)
  3. GitHub に push する
  4. この解説サイトに 1 章分の解説を追加する

この章の動作確認手順

  1. リポジトリを clone して npm install
  2. npm run build — エラーなく docs/app.js が生成されること
  3. npm run serve を実行し、表示された URL をブラウザで開く
  4. 黒い画面に灰色のノイズ風パターンと「nes1 - chapter 01」の文字が表示されれば OK
