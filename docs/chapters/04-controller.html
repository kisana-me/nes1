コントローラーの仕組み — たった 1 本の線で 8 ボタン

ファミコンのコントローラーには 8 個のボタンがありますが、本体との接続線でデータ用は実質 1 本。 どうやって 8 ボタン分を送るのでしょう?答えはシフトレジスタ(4021 相当のチップ)です。 

CPU 側の手順:
1. $4016 に 1 を書く → コントローラーが全ボタン状態を「撮影」(ラッチ)
2. $4016 に 0 を書く → 読み出しモードへ
3. $4016 を 8 回読む → A, B, Select, Start, ↑, ↓, ←, → の順に
                        1 ビットずつ出てくる

ゲーム側(6502 アセンブリ)の読み取りルーチンはこうなります:

readPad:
  LDA pad
  STA padPrev   ; 前フレームの状態を保存 (押した瞬間の検出用)
  LDA #1
  STA $4016     ; ストローブ ON
  LDA #0
  STA $4016     ; ストローブ OFF
  LDX #8
loop:
  LDA $4016     ; 1 ビット読む
  LSR A         ; bit0 をキャリーへ
  ROL pad       ; キャリーを pad へ流し込む
  DEX
  BNE loop
  RTS

8 回まわすと pad 変数の bit7 が A、bit0 が右…と全ボタンが 1 バイトに揃います。 エミュレータ側 (src/controller.ts) はこのシフトレジスタの動きをそのまま再現し、 ブラウザの keydown/keyup イベントでボタン状態を更新します。

「押した瞬間」の検出は pad AND NOT padPrev です。ジャンプや START の反応を 1 回だけにするための定番テクニックで、現代のゲーム開発でも同じ考え方を使います。

オリジナルゲーム『MOSS HOP』

苔玉の妖精「モス」が森の遺跡で胞子を集めるプラットフォーマーです。 キャラクター・世界観・ドット絵・コード、すべて本プロジェクトのための描き下ろし・書き下ろしで、 既存の商用ゲームの要素は一切使っていません。

項目内容
操作←→ 移動 / A ボタン(キーボード X)ジャンプ / START(Enter)開始
ルール各レベルの胞子を 3 つ集めると次のレベルへ。全 2 レベルで CLEAR!
形式iNES / NROM(マッパー 0)、PRG 16KB + CHR 8KB

TypeScript で書くアセンブラ

NES のゲームは 6502 の機械語です。普通は cc65 などのアセンブラを使いますが、 学習目的なのでアセンブラ自体も TypeScript で自作しました(tools/asm.ts)。 テキストをパースする代わりに、メソッド呼び出しで機械語を組み立てる EDSL 方式です: 

const a = new Asm(0xc000);
a.label("reset");
a.sei();              // → $78
a.ldaImm(0x1e);       // → $A9 $1E
a.staAbs(0x2001);     // → $8D $01 $20
a.jmp("mainLoop");    // ラベルは 2 パスで解決
const bin = a.assemble();

ラベルの位置を先に記録しておき、assemble() で分岐先アドレスを埋める 「2 パス方式」は、本物のアセンブラと同じ仕組みです。

ゲームの構造 — NMI 駆動のゲームループ

reset:                     NMI (毎フレーム VBlank):
  ハードウェア初期化           OAM DMA (スプライト転送)
  RAM クリア                 スクロール再設定
  パレット・タイトル画面描画     nmiFlag = 1
mainLoop:
  nmiFlag が立つまで待つ ◄────┘
  コントローラー読み取り
  状態に応じて分岐:
    タイトル → START でゲーム開始
    プレイ中 → 移動・物理・当たり判定・スプライト構築
    クリア   → CLEAR! 表示、START でタイトルへ
  jmp mainLoop

VRAM を触ってよいのは VBlank 中だけなので、ゲームロジックはメインループで実行し、 PPU への転送(スプライト DMA)は NMI ハンドラで行う——これが NES ゲームの標準形です。

物理演算 — 固定小数点の重力

6502 には小数がありません。そこで Y 座標と速度を 8.8 固定小数点 (上位バイト=ピクセル、下位バイト=1/256 ピクセル)で持ちます: 

; 毎フレーム: 速度 += 重力 (0.25px/f²)、位置 += 速度
LDA velYLo : CLC : ADC #$40 : STA velYLo   ; 下位バイトに加算
LDA velYHi : ADC #0        : STA velYHi    ; 繰り上がり
LDA playerYlo : CLC : ADC velYLo : STA playerYlo
LDA playerY   : ADC velYHi       : STA playerY  ; 符号付きでも動く!

ジャンプは速度に -4.5px/f($FB80)をセットするだけ。あとは重力が放物線を描いてくれます。 2 の補数表現のおかげで、負の速度も同じ加算コードで処理できるのが 6502 の美しいところです。

当たり判定 — マップはメタタイル

レベルは 16×15 のメタタイル(16×16 ピクセルのブロック)で表現します。 座標をタイル座標に変換するのは 4 回の右シフトだけ: 

; 足元 (x+2, y+16) が地面か?
LDA playerY : CLC : ADC #16
LSR : LSR : LSR : LSR      ; /16 → タイル Y
STA tileY
...
; マップ配列 index = tileY*16 + tileX
LDA tileY : ASL:ASL:ASL:ASL : CLC : ADC tileX : TAY
LDA (mapPtr),Y             ; 0 なら空、それ以外は壁/床

落下中は足元 2 点、上昇中は頭上 2 点、左右移動時は側面 2 点をチェックし、 めり込んだらタイル境界へ「スナップ」します。プラットフォーマーの基本アルゴリズムです。

エミュレータでゲームを検証する

tests/game.test.ts は、エミュレータ上で ROM を起動し自動プレイで検証します:

  1. 起動 → タイトル文字がネームテーブルに書かれている
  2. START 押下 → ゲーム状態がプレイ中になり、プレイヤーが出現
  3. 60 フレーム待つ → 重力で落下して地面に着地(onGround=1)
  4. → を 30 フレーム → X 座標が進む。← で戻る
  5. A 押下 → 16px 以上上昇し、着地すると元の高さに戻る
  6. 右へ歩き+ジャンプの自動プレイ → 胞子を 1 つ以上収集できる

エミュレータ(CPU/PPU/入力)とゲーム(物理/判定)の両方を一度に検証する統合テストです。
