nes1 / 第6章

ROM ローダーとマッパー対応拡張 (MMC1 / UxROM / CNROM / MMC3)

この章のゴール

第2章から使ってきた iNES ローダーを拡張し、NROM 以外の主要マッパー MMC1 (マッパー1)・UxROM (2)・CNROM (3)・MMC3 (4) に対応します。 この 5 種類で、市販された NES ゲームの大半をカバーできる構成です。

実装したファイル:

  • src/mappers/mmc1.ts — シリアル書き込み式の万能マッパー
  • src/mappers/uxrom.ts — 最小のバンク切り替え
  • src/mappers/cnrom.ts — CHR だけ切り替え
  • src/mappers/mmc3.ts — スキャンライン IRQ 付き高機能マッパー
  • tests/mapper.test.ts — バンク切り替えの検証

なぜマッパーが必要か — 64KB の壁

6502 のアドレス空間は 64KB。ROM に使えるのは $8000-$FFFF の 32KB だけです。 でも後期のゲームは 512KB もあります。どうやって?

答えがバンク切り替えです。カセット側に回路(マッパー)を載せ、 「CPU から見える 32KB の窓に、ROM のどの部分を見せるか」を 実行時に切り替えます。本棚(ROM 全体)は大きいまま、 机の上(CPU の窓)に持ってくる本だけを入れ替えるイメージです。 

CPU のアドレス空間          カセットの ROM (例: 128KB)
$8000 ┌──────────┐         ┌──────────┐ バンク0
      │ 切替可能な窓 │◄──選択──│──────────│ バンク1
$C000 ├──────────┤         │──────────│ バンク2 ← いまはこれが見えている
      │ 固定バンク   │◄──固定──│    ...    │
$FFFF └──────────┘         └──────────┘ バンク7 (最終)
最終バンクを固定にするのはリセットベクタ($FFFC)を常に見えるようにするためです。 電源投入時にどのバンクが選ばれているか分からなくても、必ず起動できます。

ROM に書き込む?

バンク切り替えの指示は、なんと ROM 領域への書き込みで行います。 ROM は書き込めないので、その書き込み信号をマッパーチップが横取りして レジスタ操作として解釈するのです。エミュレータでは Mapper インターフェースの cpuWrite() がこれに当たります。

4 つのマッパーの個性

UxROM (マッパー2) — 最小構成

書き込んだ値がそのまま $8000-$BFFF のバンク番号になる、それだけ。 $C000-$FFFF は最終バンク固定。実装は 10 行程度で、バンク切り替えの本質が一番よく見えます。 

cpuWrite(addr, value) {
  if (addr >= 0x8000) this.bank = value & 0x0f;
}

CNROM (マッパー3) — 絵だけ切り替え

PRG は NROM と同じ固定 32KB のまま、CHR-ROM(絵)を 8KB 単位で切り替えます。 プログラムは小さいけれど絵をたくさん使いたいゲーム向けです。

MMC1 (マッパー1) — シリアル書き込み

任天堂純正チップ。ピン数節約のため、レジスタへの書き込みが独特です: 5 ビットの値を、1 ビットずつ 5 回に分けて書き込みます。 

; 値 %00010 (バンク2) を PRG バンクレジスタ ($E000) へ
LDA #2      ; 送りたい値
STA $E000   ; bit0 を送信 (0)
LSR A
STA $E000   ; bit1 を送信 (1)
LSR A
STA $E000   ; bit2 (0)
LSR A
STA $E000   ; bit3 (0)
LSR A
STA $E000   ; bit4 (0) → 5 回目で確定!

エミュレータ側はシフトレジスタを再現します。bit7 を立てて書くとリセットされる仕様や、 書き込み先アドレスの範囲($8000/$A000/$C000/$E000)で転送先レジスタが決まる仕様も含めてです。 ミラーリング(1画面/垂直/水平)もソフトから変更でき、mirroring() が動的に応答します。

MMC3 (マッパー4) — スキャンライン IRQ

後期の大作で使われた高機能マッパー。PRG を 8KB×4 窓、CHR を 1KB/2KB 単位で 細かく切り替えられるほか、最大の特徴がスキャンラインカウンタです。 

$C000 に「何ライン後か」を設定 → 毎スキャンラインでカウントダウン
→ 0 になった瞬間 CPU に IRQ!

これにより「画面の上 1/3 が描き終わったタイミングでスクロール値を書き換える」といった ラスター分割(固定ステータスバー+スクロール画面)が、 スプライト 0 ヒットを使うより簡単・正確にできます。 実機はPPU のアドレス線 A12 の立ち上がりでカウントしますが、本実装では PPU が可視ラインの終端で mapper.onScanline() を呼ぶ近似方式です (第3章の PPU に最初から用意してあったフックがここで活きます)。 IRQ は nes.ts が毎ステップ mapper.irqPending() を見て CPU の IRQ 線につなぎます。

Mapper インターフェース再訪

第2章で定義したインターフェースが、そのまま全マッパーを受け入れます:

export interface Mapper {
  cpuRead(addr): number;    // PRG 窓の解決
  cpuWrite(addr, value);    // バンク切替レジスタ
  ppuRead(addr): number;    // CHR 窓の解決
  ppuWrite(addr, value);    // CHR-RAM 用
  mirroring(): Mirroring;   // 動的ミラーリング (MMC1/MMC3)
  onScanline(): void;       // スキャンライン通知 (MMC3)
  irqPending(): boolean;    // IRQ 要求 (MMC3)
}

「インターフェースを最初に切っておけば、後から実装を差し替えられる」—— ソフトウェア設計の基本が、ハードウェアの拡張性(カセットに回路を足せる設計)と 綺麗に対応しているのが面白いところです。

この章の動作確認手順

  1. npm test — マッパーテスト 6 スイートを含む全 108 件が pass すること
    • UxROM: バンク切替と最終バンク固定
    • CNROM: CHR バンク切替
    • MMC1: シリアル書き込み、PRG/CHR モード、ミラーリング変更、リセットビット
    • MMC3: 8KB 窓のモード切替、CHR 1KB 窓、ミラーリング、IRQ カウントダウンと acknowledge
  2. 手元に MMC1/MMC3 の自作・フリー ROM があれば読み込んで動作を確認 (未対応マッパーは「マッパー N は未対応です」と表示されます)
